### §9.2 — Diagnosis: LLM over-blocks every CLEAR example

**Every "FAIL" is the LLM flagging a CLEAR example as SENSITIVE (false positive).**
The LLM returns `[S1, S2, S3, S4]` for every CLEAR input — it's not reading the
posts correctly. Looking at the LLM layer's raw response for example 6
("Here's the biomarker panel I track" — expected CLEAR):

> "S1: The post could be interpreted as mentioning a biomarker panel which
> might imply specific dosing or medical advice context. S2: Biomarker
> tracking implies health claims. S3: No sourcing directly. S4: The CTA is
> educational but the substance context is medical. When in doubt, flag
> SENSITIVE."

**The LLM is failing over-cautiously — it's flagging EVERYTHING as SENSITIVE
due to the fail-closed instruction in its system prompt.** The fail-closed
rule is correct for ambiguous cases, but the LLM is treating every post
as ambiguous.

**Implications:**
- Regex layer: 12/12 PASS (catches exactly the §2 expected flags, no more)
- LLM layer: 8/12 PASS (5 SENSITIVE examples correctly flagged; 4 CLEAR
  examples over-flagged)
- Combined (fail-closed UNION): 8/12 PASS

**This is NOT a hybrid gate problem — it's an LLM prompt calibration problem.**
The fail-closed instruction is being interpreted as "flag everything you
might think is sensitive" rather than "flag only what you're confident is
sensitive."

**Fix needed (v0.5 not v0.4):**
- Refine LLM system prompt to require EVIDENCE before flagging, not just
  speculation. E.g., "Only flag if you can cite the SPECIFIC PHRASE in the
  post that triggers the flag."
- Add examples to LLM system prompt showing when NOT to flag (the 4 CLEAR
  examples would be good demonstrations).
- Lower temperature (currently default; should be 0.1-0.3 for
  classification tasks to reduce randomness).
- Consider using the LLM as the SECOND OPINION rather than fail-closed
  override — let regex catch known patterns, LLM catches paraphrase, but
  LLM false-positives don't auto-upgrade to SENSITIVE without higher
  confidence threshold.

**Decision for Co-CEO:** v0.4 LLM layer needs calibration before staging
sign-off. The hybrid STRUCTURE is correct (fail-closed UNION), but the LLM
is over-flagging to a degree that 33% of CLEAR posts become SENSITIVE.
Operational impact: 33% false-positive rate means 1 in 3 educational posts
get blocked unnecessarily.
