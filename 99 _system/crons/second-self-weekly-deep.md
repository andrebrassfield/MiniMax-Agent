# Second-Self Weekly Deep Session — Sunday 19:00 CT

The weekly reasoning pass that names the position Andre has been building without knowing he was building it. Reads 30 days of vault activity, produces 4 outputs. Per the 2026-06-22 Path A spec — extends the existing `ea-weekly-connections` workflow with the "emerging thesis" output the article prescribes.

The article: "This session should be uncomfortable."

**EXECUTE the procedure:**

## Step 1 — Gather the 30-day input set

```bash
find ~/MiniMax-Agent/01\ Daily ~/MiniMax-Agent/02\ Notes ~/MiniMax-Agent/03\ Projects \
  -type f -name "*.md" -mtime -30 2>/dev/null | sort
```

**HALT** if total count < 5 (insufficient material; exit silently with `<mavis-progress>second-self-weekly-deep: skipped — <N> notes in window</mavis-progress>`).

## Step 2 — Read the input set

Read every file in the gathered set. Extract:
- The recurring positions Andre has taken (from `02 Notes/ideas/`, `02 Notes/patterns/`, daily notes)
- The recurring sources Andre has been engaging (from `02 Notes/articles/`)
- The active projects (from `03 Projects/*/`)
- The open questions (from `02 Notes/questions/`, `MAVIS.md` open questions section)

## Step 3 — Run the weekly deep prompt

> Read everything added to my Obsidian vault in the last 30 days.
>
> Produce four outputs:
>
> **Emerging thesis:** what position is forming in my thinking that I have not named yet?
>
> **Full contradiction map:** where do my documented positions conflict with each other or with recent sources?
>
> **Knowledge gaps:** based on what I am reading and thinking about, what perspective is clearly absent?
>
> **One action:** the single highest-leverage thing I could research or write this week.
>
> Be specific. Reference note titles. This session should be uncomfortable.

The 4 outputs are NOT optional. If any output is "I don't know," that's the data — the system is telling Andre he needs to do the work, not that the cron failed.

## Step 4 — Write the weekly deep session

Output to `00 Inbox/weekly-deep-YYYY-MM-DD.md` (mirror to `~/MiniMax-Agent/99 _system/weekly-deep/weekly-deep-YYYY-MM-DD.md`).

```markdown
---
date: YYYY-MM-DD
type: second-self-weekly-deep
input_window: last 30 days
notes_read: <N>
week: <ISO week number>
---

# Weekly Deep Session — YYYY-MM-DD

> Auto-generated by `second-self-weekly-deep` cron. This session should be uncomfortable. Read it before Monday.

## Emerging Thesis

<2-4 paragraphs naming the position that has been forming across the last 30 days. Reference 3+ note titles that contain pieces of it.>

The position you have not named yet is: **<one sentence>**

## Full Contradiction Map

### Internal contradictions (your ideas vs your other ideas)
- **<idea A>** vs **<idea B>** — <quote both, name the friction>
(repeat as needed)

### External contradictions (your ideas vs recent sources)
- **<idea X>** vs **<source Y>** — <quote both, name the friction>
(repeat as needed; consume this week's 7 contradiction checks from `second-self-contradiction`)

## Knowledge Gaps

- **<gap 1>** — <what's missing and why it matters>
- **<gap 2>** — <what's missing and why it matters>
(repeat; 3-5 gaps)

## One Action

**Do this week:** <one specific thing, with the deliverable named, the time estimate, and the connection to the emerging thesis>

Not "research X" — name the artifact. "Write the Mavis-as-companion essay (1,500 words) and post to the vault. Connects to emerging thesis because..."

---

**Process notes:**
- Input set: <N> notes across <folders>
- Contradiction checks consumed: 7 (last week)
- Halt conditions checked: pass
- This week's discomfort level: <low | medium | high>
```

## Step 5 — Surface aggressively

This cron ALWAYS sends a Telegram nudge. The article says "This session should be uncomfortable" — discomfort requires Andre actually reading it.

> "Weekly deep session ready: `00 Inbox/weekly-deep-YYYY-MM-DD.md` — emerging thesis: <one-line summary>. Discomfort level: <low|medium|high>."

If discomfort level = high: send a second nudge Monday morning at 08:00 CT as a reminder.

## Hard constraints

1. **All 4 outputs required.** No section can be empty. If Mavis can't produce one, that's the data — Andre needs to do work to surface it.
2. **Reference note titles.** No vague claims. Every assertion cites ≥1 specific note from the input set.
3. **Discomfort is the goal.** Per the article: "This session should be uncomfortable." If the brief is comfortable, the cron is broken — the work isn't being done.
4. **The One Action is a deliverable, not a topic.** "Research X" is wrong. "Write the 1,500-word essay on Y" is right.
5. **No cross-team reads.** Same as the others.
6. **Append to log.** Every run appends to `~/.mavis/state/second-self-weekly-deep.log`.

## Failure modes

| Failure | Detection | Recovery |
|---|---|---|
| Output reads like a summary (no emerging thesis named) | Step 4 inspection | HALT, surface — the prompt isn't pushing hard enough |
| All 4 outputs are "I don't know" | Step 4 inspection | Log warning — the input set might be too thin or too scattered |
| Telegram send fails | Step 5 errors | Log; the file is still on disk |
| Same emerging thesis appears 3 weeks in a row | Cross-week pattern check | Log warning — the cron is in a loop, Andre isn't engaging with the output |
