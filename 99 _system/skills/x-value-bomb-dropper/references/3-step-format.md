# 3-Step Format — x-value-bomb-dropper

The 3-beat structure every value-bomb reply follows. The
Scribe fills in this template with source-question-specific
stack and steps, not a copy of the template.

## The 3 beats

| Beat | Purpose | Length | Example opener |
|---|---|---|---|
| 1. Name the stack | Specific tool names. Not "use a tool" — actual stack. | 1 sentence, 40-70 chars | "Use Vapi + Google Calendar + Zapier." |
| 2. First concrete step | Action the person can take this week. | 1-2 sentences, 80-130 chars | "Sign up for Vapi. Connect Google Calendar. Build a 5-min voice agent that books a 30-min slot when the caller says 'schedule me in.'" |
| 3. Second step + unit economics | Follow-on action + cost/payback number. | 1-2 sentences, 80-130 chars | "Wire the slot to ServiceTitan via Zapier. Cost: ~$0.40/call. Replaces a $22/hr CSR. Payback in 3 weeks." |

**Total:** 200-330 chars. **Hard cap 280 single-tweet, ~840
char 🧵 thread (3 × 280).** Scribe picks format based on
question complexity.

## Format options

### Single-tweet format (target 200-280 chars)

Dense 3-step. Use when the question is narrow and the
specifics fit.

**Example skeleton (NOT a real draft, just a template):**
> "Use Vapi + Google Calendar + Zapier. Step 1: sign up for Vapi, connect your Google Calendar, build a 5-min voice agent that books a 30-min slot when the caller says 'schedule me in.' Step 2: wire the slot to ServiceTitan via Zapier. Cost ~$0.40/call. Replaces a $22/hr CSR. Payback in 3 weeks."

### Thread format (🧵 marker on tweet 1, 3 tweets total)

Use when the question needs the breathing room. Each tweet
is a step. Total ~600-840 chars across the 3 tweets.

**Example skeleton:**
> "Use Vapi + Google Calendar + Zapier. 🧵 1/ Sign up for Vapi. Connect your Google Calendar. Build a 5-min voice agent that books a 30-min slot when the caller says 'schedule me in.' 2/ Wire the calendar slot to ServiceTitan via Zapier. Map the customer's name, address, and slot to the existing job fields. Test with a fake call. 3/ Cost: ~$0.40/call all-in. Replaces a $22/hr CSR. Payback in 3 weeks on volume as low as 8 calls/day."

## What makes a strong value-bomb stack

The stack naming is the load-bearing element. A strong stack
is:
- **Specific** (named tools, not "use a platform")
- **Operational** (the person can actually buy/sign up for
  each tool this week)
- **Fits the question** (Shopify Admin API for inventory
  sync, not for call automation)
- **Free or cheap** (free tiers preferred; the value is the
  architecture, not the tool cost)

**Good stack examples:**
- "Vapi + Google Calendar + Zapier" (voice agent + scheduling)
- "Shopify Admin API + Node.js middleware + Postgres ledger"
- "Make + Airtable + Slack" (low-code ops automation)
- "Cloudflare Workers + D1 + Resend" (serverless transactional email)
- "n8n + GPT-4o-mini + Notion" (AI workflow automation)

**Bad stack examples (the "vague stack" violation):**
- "Use a tool" (vague)
- "Find the right platform" (vague)
- "AI" (vague)
- "Build it yourself" (vague)

## What makes a strong tactical step

Each of the 3 steps is a specific action the person can take
this week. A strong step is:
- **Specific** (named tool + named action + named outcome)
- **Boring** (the person can do it without learning anything
  new beyond the tool's basic UI)
- **Concrete** (the person knows they've done it — "did I
  sign up for Vapi?" is yes/no)
- **Verifiable** (there's a clear "this step is done" signal)

**Good step examples:**
- "Sign up for Vapi. Connect Google Calendar. Build a
  5-minute voice agent that books a 30-minute slot when the
  caller says 'schedule me in.'"
- "Wire the calendar slot to ServiceTitan via Zapier. Map
  customer name, address, and slot to existing job fields.
  Test with a fake call."

**Bad step examples (the "vague step" violation):**
- "Learn the tool" (vague)
- "Try it out" (vague)
- "Figure out the right approach" (vague)
- "Set it up" (vague)
- "Integrate with your workflow" (vague)

## What makes a strong unit-economics line

The unit-economics line is the trust signal. A strong line is:
- **Concrete** (a real number, not "save time")
- **Comparable** (vs. the human cost it replaces)
- **Time-bound** (payback period, hours saved per week,
  cost per call)

**Good unit-economics examples:**
- "~$0.40/call all-in. Replaces a $22/hr CSR. Payback in 3
  weeks."
- "Saves 6 hours/week. Pays back in 2 weeks."
- "Cost: $0.02 per invoice. Manual cost: $4.50 per invoice.
  225x cheaper."

**Bad unit-economics examples (the "vague economics" violation):**
- "Save time" (vague)
- "Reduce costs" (vague)
- "Improve efficiency" (vague)
- "Better customer experience" (vague)
