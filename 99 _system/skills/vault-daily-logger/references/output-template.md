# Output Template — vault-daily-logger

The markdown file structure for the auto-generated daily note.

## File path

`01 Daily/YYYY-MM-DD.md`

## Template

```markdown
---
date: YYYY-MM-DD
day: <DayOfWeek>
type: daily
tags: [auto-generated]
generator: vault-daily-logger
generator_version: 1.0
---

# YYYY-MM-DD, <DayOfWeek>, <Month> <Day>, <Year>

> **AUTO-GENERATED** by `vault-daily-logger` at 18:00 CT on YYYY-MM-DD. The chief did not write a manual daily for this date. The 5 bullets below are the day's actual technical footprint (files modified in `03 Projects/`), grouped by top-level project, top 5 by modification count. Edit this file to add manual context — subsequent cron runs will halt.

## 5-bullet technical footprint

- **<Project name 1>** — <N> files modified. <1-line summary>. Key files: <path1>, <path2>, ...
- **<Project name 2>** — <N> files modified. <1-line summary>. Key files: <path1>, <path2>, ...
- **<Project name 3>** — <N> files modified. <1-line summary>. Key files: <path1>, <path2>, ...
- **<Project name 4>** — <N> files modified. <1-line summary>. Key files: <path1>, <path2>, ...
- **<Project name 5>** — <N> files modified. <1-line summary>. Key files: <path1>, <path2>, ...

## (Optional) Stubs for manual follow-up

- 🎯 Most Important Thing Today: <to be filled by the operator>
- 📥 Captures: <to be filled by the operator>
- ✅ Confirms: <to be filled by the operator>
- 🚧 In-flight: <to be filled by the operator>
- 🧹 Vault hygiene: <to be filled by the operator>

## Notes for the chief

- Cron run completed at HH:MM:SS CT. The 5-bullet summary was generated by scanning `03 Projects/` for files modified today.
- Total files modified today: <N>. Top 5 projects captured. If <5 projects had activity, the bullets are fewer (or just one bullet if only one project).
- The next cron run is scheduled for 18:00 CT tomorrow.
- **Manual-detection:** this file was generated because the daily was missing or had <100 bytes of body content. The next cron run will halt if this file has been edited.
```

## Why the AUTO-GENERATED callout is the load-bearing element

A future Mavis session might read this daily to ground her context.
The `> **AUTO-GENERATED**` callout + the `tags: [auto-generated]`
frontmatter tell her: "this is not a manual daily, it's a
fallback." Without that marker, Mavis might treat the 5-bullet
summary as Andre's intent for the day (it isn't — it's just the
file-mod activity).

The marker is also what tells the manual-detection logic: "this
file was generated by a machine; treat it as auto-generated even
though the body is >100 bytes." The next cron run's body-size
check would otherwise think the operator wrote a real daily.

## Why the optional stubs are present

The operator's manual dailies (per the existing convention) use
the 🎯 / 📥 / ✅ / 🚧 / 🧹 template. By including empty stubs in
the auto-generated daily, the operator can convert it to a manual
one by filling in the stubs — no template-switching needed.

The empty stubs are also a visual cue: "this is a daily, not a
5-bullet report" — the stubs are the template's signature.

## Filename collision check

If the file already exists, the skill halts. It does NOT
overwrite. Even if the existing file is auto-generated, the next
cron run will skip it (body size > 100 bytes, treated as
"operator's manual work").

This is intentional: the auto-generated daily is a snapshot of the
day's activity. Re-running the skill on the same day would change
the bullets (more files modified, different top project), which
would be a silent overwrite of a real historical record. The
halt-and-skip is the right behavior.
